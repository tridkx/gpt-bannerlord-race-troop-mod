# 种族角色布料模拟（明确请求后读取）

仅在用户明确要求制作、启用或返修布料模拟时读取本专题及下游布料参考。衣裙、袖子、披风或长发的存在、普通蒙皮穿模、制作“完整角色”均不自动触发模拟。未请求时按普通蒙皮制作与动作检查，不新增 cloth 数据、烘焙、碰撞配置或 `mod.json.cloth_diagnostics`。已有布料数据和用户改动保留，不因默认规则擅自删除或停用。

## 制作与返修

- 布料资源使用已安装的[装备技能](../../bannerlord-equipment-mod/SKILL.md)中的相关流程，按任务读取其布料参考；角色仍保留源比例与自有绑定骨架。
- 先区分静态源网格间隙、绑定方向、蒙皮、实际动画与模拟碰撞问题。站立也有臀部穿裙时，已纳入模拟范围的任务读取[碰撞拟合与覆盖](../../bannerlord-equipment-mod/references/cloth-collision.md#拟合与覆盖)，不能通过改变角色比例掩盖问题。
- 参数、活动分区、碰撞体和检查动作须逐模型核对；不复制 Wudu 或天香的胶囊、顶点编号、Alpha、活动距离或其他专用参数。LOD 减面与模拟动态分别检查。
- 最终 TPAC 回读任务布料数据及所有交付 LOD，检查当前角色骨架、映射、约束和匹配的预处理数据；源 Blend/FBX 与交付资源保持可重建。

## 离线诊断与交付

最终 TPAC 验证后，按本角色骨架、碰撞体与动作配置离线诊断，读取装备技能的[自动诊断与交付接入](../../bannerlord-equipment-mod/references/offline-cloth.md#自动诊断与交付接入)。工作区要求接入共用 `tools/cloth_simulator/pipeline.py` 时，核对工具 README 的字段与边界，逐模型核对资源名、检查 LOD、动作采样率和碰撞体，初次接入使用报告模式。不支持的代理映射不得作为通过；用户只要求共用工具接入时，不为其他既有模组启用配置。

近似诊断、离线蒙皮预览和游戏布料求解是不同证据，不能互相代替或自动更改游戏验收状态。游戏由用户测试，按明确范围记录站立、跑动、持武器、骑乘及所需 LOD 的反馈。助手不启动游戏，不改 Native，只安装任务模块并保留旧交付包。
